# 18 — Math / Geometry
## GRAMMAR STATUS: COMPLETE AS A FAMILY SYSTEM

Math/Geometry must not be forced into one universal structure.

The correct representation is chosen from the actual mathematical space.

## Family selection

```text
numeric adjacency   → number line
2D point relation   → coordinate plane
digit operations    → digit row / column
prime sieve         → number grid
cyclic state        → circle / state cycle
vector / direction  → arrow geometry
range / sweep       → interval-axis grammar
```

## Kit mapping

### Number line
```text
axis     → RoughLine
ticks    → RoughLine
labels   → ChalkText
marker   → compact chalk point
```

### Coordinate plane
```text
axes     → RoughLine
points   → compact round chalk nodes
segment  → RoughLine
curve    → RoughCurve / EvolvingPath
```

### Digit row
```text
digit slot → RoughBox
digit      → ChalkText
carry      → ChalkText / small pointer
```

### Sieve
Use Matrix/Grid grammar with numeric cells.

### Cyclic state
```text
state node   → round chalk node
cycle edge   → RoughCurve / EvolvingPath
active path  → PathTracer
```

## Adaptive sizing

Representation follows the active mathematical domain.
Do not invent a fixed dashboard template.

## State colors

Use normal course semantics:
query cyan, current pivot, confirmed good, reject warn, history dim.

## False semantics

Never:
- force geometry into cards when coordinates/segments are the meaning,
- use arbitrary screen spacing that contradicts numeric scale when scale matters,
- imply a number line is an Array,
- imply coordinate distance is meaningless when geometry depends on it.

## Permanent rule

```text
MATH CHOOSES THE TRUTHFUL MATHEMATICAL SPACE.
THE COURSE DOES NOT FORCE EVERYTHING INTO BOXES.
```
